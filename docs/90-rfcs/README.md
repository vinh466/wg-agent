# RFCs — proposals under discussion

Proposals that are **not yet accepted**. Nothing here is normative and nothing here is
implemented.

## When an RFC is required

Write one when a change:

- Touches several spec modules
- Carries an architectural trade-off that needs discussion
- Might break API compatibility
- Introduces a significant new dependency

Skip the RFC for small, obvious changes — amend the spec directly.

## Lifecycle

```
Draft ──► Discussion ──► Accepted ──► ADR + spec update ──► archive
                   └───► Rejected ──► retained with the reason
```

A rejected RFC is **retained**. It stops someone proposing the same idea six months later
without knowing it was already considered.
